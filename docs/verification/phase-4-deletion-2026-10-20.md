# Phase 4 candidate deletion proof — 2026-10-20

The inactive document candidate now implements the planned `DELETE /v1/documents/{id}?scope=...` contract. Browser deletion requires an active session, exact origin and CSRF token; application deletion requires `document:delete`, matching scope and approved IP. The private socket derives no public identity and checks the namespace/scope supplied by the authenticated gateway. Missing and inaccessible IDs return 404; an active worker returns 202 until its native unit exits; an inactive job returns 204 after its encrypted row is removed.

The private job-store schema moved from version 1 to version 2 with a deletion-intent table. Opening a verified version-1 candidate store upgrades it transactionally; foreign database identities remain rejected. An active deletion is durable across supervisor restart. Native cleanup confirmation is required before the cancelled claim and deletion marker are removed. This schema is separate from the enrolled phase-3 account database, which was not migrated.

RED→GREEN tests cover foreign ownership, browser CSRF, bearer capability and scope, inactive removal, active deletion across reopen/recovery, and version-1 candidate migration. Windows full suite: 241 passed, 7 Linux-only skips, 0 failed. Debian full suite: 248 passed, 0 skipped, 0 failed. On the disposable Debian 13 LXC, the temporary supervisor completed a multilingual browser request, deleted it through the injected HTTP path, and returned 404 for the subsequent status lookup. A separate real transient slow worker was cancelled and its encrypted job disappeared only after native unit cleanup. Both native proofs reported no active document units and the enrolled gateway PID remained 19963. The package inventory checksum remained unchanged.

The deployed gateway does not inject the document client and still returns 404 for these paths. OCR/rich processing, sustained joint load, coordinated production activation and the whole Phase 4 release gate remain blocked. Deletion removes live logical records; encrypted SQLite pages may persist in storage snapshots and backups until their normal lifecycle expires, so this is not a forensic media-erasure claim.
