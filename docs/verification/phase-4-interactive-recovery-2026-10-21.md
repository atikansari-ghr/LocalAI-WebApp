# Phase 4 offline interactive lease recovery candidate — 2026-10-21

An interrupted interactive lease still blocks document claims across supervisor restarts. The new offline barrier operation refuses a missing, malformed, writable or replaced marker, keeps it in place when verification fails, and synchronizes its removal only after a positive proof. The systemd proof requires the gateway, private chat worker, embedding worker and document supervisor to each report a masked unit, inactive/dead state, zero main/control PID and no control group on two consecutive reads. Normal supervisor startup never calls this recovery operation. Independent review found that two reads cannot prevent a privileged actor from restarting a unit before marker removal. The standalone production recovery entrypoint was removed; the verifier and protected barrier remain internal pieces for a future exclusive, journaled maintenance workflow.

RED→GREEN tests first failed because the recovery operation and unit verifier were absent. Focused Debian tests pass 7/7, including marker replacement, unmasked/active/lingering units and malformed systemd output. At source `e907999`, the Windows full suite passed 264 tests with 21 Linux-only skips, while a fresh Debian checkout passed 285/285 with zero skips. A native Debian proof from that exact checkout created disposable synthetic units and a separate root-owned marker. It rejected an active unit and the real active Local AI units, then cleared the synthetic marker and resumed a synthetic document claim only after four vendor-location proof units were runtime-masked and stopped. The real gateway, chat and embedding PIDs remained 19963, 19679 and 19718, `/var/lib/dpkg/status` retained SHA-256 `6472c8846aa1c77e2616b8d74b53818517e921a27048edbe61686527073c67fe`, and all synthetic files/masks were removed.

The same proof exposed a production limitation: a runtime mask under `/run/systemd/system` does not override an installed unit file under `/etc/systemd/system`. A disposable `/etc` unit remained loaded/static and the verifier correctly rejected it. The deployed gateway and private worker unit files use `/etc`, so no production marker is eligible for clearing by this candidate alone. A journaled maintenance workflow must first establish an effective mask or equivalent exclusive stop for those exact units, prevent concurrent unit changes until marker removal completes, preserve their prior files/states, and prove rollback before this becomes an operational recovery path. The live gateway is not wired to the lease, no Phase 4 supervisor is installed, and the whole Phase 4 release gate remains blocked.
