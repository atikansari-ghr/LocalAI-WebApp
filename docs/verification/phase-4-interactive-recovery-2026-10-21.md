# Phase 4 offline interactive lease recovery candidate — 2026-10-21

An interrupted interactive lease still blocks document claims across supervisor restarts. The new offline barrier operation refuses a missing, malformed, writable or replaced marker, keeps it in place when verification fails, and synchronizes its removal only after a positive proof. The systemd proof requires the gateway, private chat worker, embedding worker and document supervisor to each report a masked unit, inactive/dead state, zero main/control PID and no control group on two consecutive reads. Normal supervisor startup never calls this recovery operation. Independent review found that two reads cannot prevent a privileged actor from restarting a unit before marker removal. The standalone production recovery entrypoint was removed; the verifier and protected barrier remain internal pieces for a future exclusive, journaled maintenance workflow.
