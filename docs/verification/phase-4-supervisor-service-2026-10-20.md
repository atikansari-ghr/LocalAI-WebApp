# Phase 4 private supervisor service checkpoint — 2026-10-20

An inactive root systemd service candidate now owns the private encrypted document job store and one native job runner. Its service definition gives it a root-only state directory, private network/devices/tmp, read-only system files, no new privileges, restricted address families, explicit memory/zero-swap/CPU/task limits and exclusions for the enrolled gateway, model and configuration state. It restarts on failure. On a requested stop, the process aborts active work, waits for native cleanup and rechecks the transient-unit inventory before exiting. A missing database beside an existing key requires recovery instead of silently creating a replacement store.

On the disposable Debian 13 LXC, `systemd-analyze verify` accepted the candidate unit file. A separate restricted transient service ran the same entrypoint against a disposable root-only encrypted store, completed a synthetic multilingual TXT job, retained an active supervisor process, then stopped cleanly. Its worker unit had no remaining main PID, no document-job units remained active, and the enrolled gateway PID stayed unchanged. A missing worker was rejected before creating a key. A shutdown regression confirms that stopping during startup recovery cannot claim or launch a job. The unit's stop timeout allows native cleanup and recovery to finish. This proof used a candidate copy under `/opt/localai/documents/candidates/`; it did not install, enable or switch the user's live service.

The candidate now has a private Unix socket at `/run/localai-documents/document.sock`, restricted by a root-owned directory and the `localai` group. It accepts one bounded request per connection for encrypted job submission, scoped status/result and cancellation. Exact identity, scope, operation, upload encoding and fields are checked before store access; four connections and an absolute 15-second frame deadline bound stalled clients. The gateway-side client also bounds response size and duration and handles cancellation, disconnects and malformed replies. The disposable native proof used that client as the actual `localai` service account to read a completed result; a foreign scope returned no result. No active job units remained and the live gateway PID was unchanged. Independent review reproduced and fixed a full 10 MiB base64 parser stack overflow and indefinite slow-client slot occupation; regressions now pass on Debian. No public gateway route uses this socket yet, and the service is not installed or activated. Authenticated HTTP derivation of identity/scope, service restart with an active worker, safe onboarding of root-only state/key, coordinated updates/rollback, real OCR adapters, sustained joint 6 GiB resource use and full release checks remain Phase 4 gates.
