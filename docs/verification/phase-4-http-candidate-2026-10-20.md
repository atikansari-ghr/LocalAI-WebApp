# Phase 4 gated document HTTP candidate — 2026-10-20

An injected document-client candidate enables asynchronous OCR/extract submission and scoped job status in the gateway handler for isolated tests. The deployed gateway does not inject this client and still returns 404 on these paths. Deletion, full structural qualification, installed-service restart and release acceptance remain blocked.

Browser calls derive `user:<id>` from a current session. Submission requires exact HTTPS Origin and CSRF; status still requires the session. Bearer calls derive `app:<id>` only after checking the operation capability, source IP and requested scope, and reject a browser cookie. The request cannot choose either namespace. Submission checks the idempotency key, exact fields, canonical base64, size, filename, declared media type and preliminary magic/UTF-8 before passing bytes to the root-only socket; the worker remains responsible for complete format validation. Duplicate or inaccessible status queries are rejected. Absent or inaccessible jobs share a 404 response.

The authorization test reproduced a scoped application read failing because an early capability check omitted the mandatory scope. It now authenticates the scoped status request once, after parsing the query. Review also found that many unfinished 14 MiB uploads could exhaust the 512 MiB gateway before the four-connection supervisor limit mattered. The handler now reserves at most two upload slots before reading, holds them through response completion, and applies an absolute 15-second read deadline. A test holds two authenticated partial uploads, observes 429 on a third, disconnects both and then succeeds with a new submission. Browser CSRF, application scope and revocation, mixed identity, bad media/settings, duplicate query scope and idempotency-conflict paths pass against the isolated handler. No live document route or service was enabled.
