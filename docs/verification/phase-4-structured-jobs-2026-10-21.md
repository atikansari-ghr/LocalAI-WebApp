# Phase 4 private structured-job store candidate — 2026-10-21

A separate encrypted SQLite WAL candidate now persists structured-extraction requests and reviewed results. It validates the data-only schema and parser/OCR source units before enqueue, binds idempotency to the owner and exact request, and keeps document text, schema and result behind a per-job envelope key. Existing foreign database files are rejected before mutation. A claim token prevents a stale model response from completing a job after interruption; recovery requires an explicit confirmed interactive-recovery proof and records an interrupted job as failed rather than replaying an uncertain inference call.

The initial focused test failed because the module was absent, then passed after implementation. The tests reopen the database, check owner/scope isolation, inspect on-disk database and WAL bytes for private text, reject changed requests under the same idempotency key, reject incompatible databases, and deny late completion after interrupted-claim recovery.

Independent review found three Important gaps in the first checkpoint. RED→GREEN regressions now hide expired jobs and results, purge expired nonrunning records, and retain an expired running claim until confirmed recovery. Completion accepts raw model candidate text and reruns schema, literal-value and citation checks against the encrypted saved evidence before writing a result; an invented cited value is rejected. Enqueue persists a bounded normalized copy made from validated evidence, so an input `toJSON` method cannot replace the report after validation. These fixes still require full-suite and CI verification at their final source.

The source-only private runner now serializes claims. Its generator calls the existing bounded evidence checker through a supplied qualified inference client, then the store independently reassesses candidate text against its saved evidence before completing the job. A failed or invalid model response leaves the claim running and blocks further runner steps until a separately confirmed recovery marks the interruption. Focused tests cover successful persistence, two simultaneous steps, a model failure and a fabricated citation. The disposable Debian model proof used the real local model and shared interactive lease on a fixed English/Arabic invoice. It found the invoice ID, date and total with exact source citations, persisted the checked result, reopened the encrypted queue and recovered the same result. The deployed gateway PID stayed unchanged and the host used zero swap. This is one synthetic quality case, not broad accuracy qualification.

## Private supervisor queue boundary — 2026-10-22

The inactive document supervisor opens the separate structured SQLite WAL store with its existing vault and accepts bounded `submit-structured` and `structured-status` commands over its permission-restricted Unix socket. The caller supplies the already authenticated namespace and scope. The queue validates schema and source evidence again; duplicate requests return the same job, and foreign owners/scopes cannot read it. A Linux socket test closed and reopened the store and socket, then recovered the queued receipt. On the disposable Debian LXC, a source-only supervisor process accepted a structured request, returned scoped status, stopped cleanly, and left the encrypted job readable after reopen. The gateway/chat/embedding PIDs and package-status digest stayed unchanged. This did not install or activate a Phase 4 service.

The supervisor service remains isolated from network and model credentials. Its queue is deliberately not consumed inside that sandbox. The separate model runner has not been connected to the supervisor, so these jobs remain queued until an inference bridge, cancellation, lease recovery and coordinated backup/restore are qualified. The public gateway has no structured-extraction route. Full suite and CI results for this checkpoint are recorded in progress tracking after verification.

Focused review found that an existing vault and document DB could start with a missing structured DB, silently replacing lost structured jobs with an empty queue. The disposable native restart proof first failed on that condition, then passed after startup required all three state files to exist together or all three to be absent for first initialization. A future migration from an older document-only state must be an explicit, separately reviewed operation; this source-only Phase 4 service has never been installed on the live host.
