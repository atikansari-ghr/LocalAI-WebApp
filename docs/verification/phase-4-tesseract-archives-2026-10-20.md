# Phase 4 Tesseract archive provenance candidate — 2026-10-20

The isolated Tesseract candidate has 46 `.deb` archives in its build cache. The read-only target harness `tests/target/tesseract-deb-provenance.mjs` obtained each archive's package name, version and architecture from `dpkg-deb`, then matched its SHA-256 to an exact version/architecture local APT package-index record. It independently matched every candidate to a Debian main `Packages` entry and verified the three relevant `Packages` files against SHA-256 and size entries in their cached `InRelease` metadata. All 46 matched. The main OCR package is `tesseract-ocr` 5.5.0-1+b1; the English and Arabic language packages are each 1:4.1.0-2. The official [Debian Trixie package entry](https://packages.debian.org/trixie/tesseract-ocr) provides upstream package context. The harness did not install these archives into the active Debian system.

The companion `tests/target/tesseract-payload-reconstruction.mjs` rebuilt all 46 archives under a restricted temporary `/root` directory and compared the resulting tree to the candidate's `root` with `diff -qr --no-dereference`. The file set, file contents and literal symlink targets matched exactly; both trees contain 576 regular files and 72 symlinks. The temporary reconstruction was removed. This is evidence about the extracted candidate bytes, not activation or a qualified immutable installer payload.

On 2026-10-21, the companion `tests/target/tesseract-release-signatures.mjs` checked the separately downloaded Debian `gpgv-static` 2.4.7-21+deb13u1+b5 archive against SHA-256 `cf12335ce3a8c6994a2008cd04cdf4d8e1e84a6d2e1aa9c78e3a6d4c235c2911` in the Release-linked package list. It extracted the verifier only under `/root`, then used the locally installed Debian archive keyring to validate the cached trixie, trixie-updates and trixie-security `InRelease` signatures. All three passed. Debian describes this [Release → Packages → archive authentication chain](https://www.debian.org/doc/manuals/debian-handbook/sect.package-authentication.en.html); the [gpgv-static package](https://packages.debian.org/trixie/gpgv-static) supplies the standalone verifier. No package was installed into the active LXC, and the verifier extraction was removed.

Together these checks establish a locally revalidated signed Debian metadata chain, archive hashes and reconstructed-tree equality, subject to trusting the LXC's existing Debian archive keyring and verifier implementation. They do not independently audit extracted file ownership/modes against package metadata or the full native library and trained-data license obligations. The candidate tree still contains build caches and font-configuration links outside the candidate root, so the installer must define and qualify a smaller immutable runtime payload. The known strict English OCR mismatch (`AI` read as `Al` by Tesseract on the fixed synthetic image) remains a separate release-quality failure and was not waived by archive integrity.

The enrolled gateway remained at PID 19963 and `/var/lib/dpkg/status` retained SHA-256 `6472c8846aa1c77e2616b8d74b53818517e921a27048edbe61686527073c67fe`. No Phase 4 document unit was activated. This evidence is preliminary and does not pass the whole Phase 4 release gate.
