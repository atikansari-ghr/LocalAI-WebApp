# Phase 4 Tesseract archive provenance candidate — 2026-10-20

The isolated Tesseract candidate has 46 `.deb` archives in its build cache. The read-only target harness `tests/target/tesseract-deb-provenance.mjs` obtained each archive's package name, version and architecture from `dpkg-deb`, then matched its SHA-256 to the exact version's current local APT package-index record. All 46 matched. The main OCR package is `tesseract-ocr` 5.5.0-1+b1; the English and Arabic language packages are each 1:4.1.0-2. The official [Debian Trixie package entry](https://packages.debian.org/trixie/tesseract-ocr) provides upstream package context. The harness did not install these archives into the active Debian system.

This check establishes archive-to-local-index agreement, not a fully signed provenance chain. It did not revalidate the APT index's Release signature in this run, compare every extracted installed file to its archive, or audit the full native library and trained-data license obligations. The candidate tree still contains build caches and font-configuration links outside the candidate root, so the installer must define and qualify a smaller immutable runtime payload. The known strict English OCR mismatch (`AI` read as `Al` by Tesseract on the fixed synthetic image) remains a separate release-quality failure and was not waived by archive integrity.

The enrolled gateway remained at PID 19963 and `/var/lib/dpkg/status` retained SHA-256 `6472c8846aa1c77e2616b8d74b53818517e921a27048edbe61686527073c67fe`. No Phase 4 document unit was activated. This evidence is preliminary and does not pass the whole Phase 4 release gate.
