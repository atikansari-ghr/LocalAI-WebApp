# Phase 4 internal structured-extraction candidate — 2026-10-20

This candidate runs **after** parsing/OCR and outside the background document worker. Its input is a bounded parser report, a versioned flat scalar schema, and the existing qualified private chat client. It builds citations only from parser/OCR units, attaches the document SHA-256 to every source, bounds evidence to 128 units and 16 KiB of text, and sends at most 12 KiB of schema plus evidence to the local model. No caller-provided model endpoint, executable path or web URL is used. The inference client must be supplied with shared interactive admission by its caller; the native proof used the inactive Unix lease candidate. The deployed gateway has no structured-extraction route or document client.

The result checker accepts JSON with insignificant whitespace but rejects duplicate or ambiguous JSON keys, unknown schema fields, invented evidence IDs, empty or invalid values, non-literal values, and partial word/number matches. It retains absent fields as `missing`, distinct model-proposed values as `conflict`, and all results as `reviewRequired`. A literal citation is evidence that a value occurs in a source unit, **not** proof that the value has the requested semantic meaning. It cannot establish that the model found every occurrence or every conflict; human review remains required.

The first real-model run was rejected. The local model returned a labeled Arabic invoice value and an amount with a currency suffix, both incompatible with the schema, plus insignificant JSON whitespace. The candidate then learned to ignore whitespace outside strings without weakening duplicate-key rejection, and its prompt specified the three field formats. A fresh run on a fixed synthetic English/Arabic invoice returned `INV-42`, `2024-02-29` and `120.50`, each with valid unit citations, using the private llama.cpp chat service through a temporary interactive lease. Its result was marked review-required. The source document digest was `6837ebbe9c995456d6e20eed6d02fee603ddeb21e03f4fa8387702df3ee6578d`. This is one successful proof, not a statistical accuracy qualification.

Focused unit tests cover parser versus OCR source identity, missing and conflicting fields, forged citations, invalid dates/amounts/identifiers, duplicate-key JSON, whitespace, and the inference adapter. The native target harness is `tests/target/document-structured-model.mjs`; it runs only with `TARGET_TEST_LXC=disposable` as root.
