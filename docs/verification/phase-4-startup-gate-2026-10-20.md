# Phase 4 startup gate checkpoint — 2026-10-20

An inactive in-process gate serializes native unit recovery and document launches. It calls the job recovery callback only after leftover units have been stopped and checked. A launch cannot begin while that recovery is pending. It runs one document unit at a time; a failed recovery blocks launch, and an unconfirmed cleanup makes the next launch repeat recovery. Focused RED→GREEN tests exercise each boundary. The root-only Debian proof also ran the gate with actual systemd recovery and a multilingual transient worker, then confirmed cleanup and unchanged live gateway PID. Independent review found no high-priority issue within this stated scope. Full Windows validation passed 221 tests with three POSIX-only skips; Debian passed 224/224 with zero skips; documentation checks passed.

This is a building block, not the persistent document supervisor. It does not itself lock out a second process, own the job database, map a job to a running unit, accept authenticated gateway requests or manage service restart. A single-instance root systemd service and crash/cancellation proof are required before this gate can protect live jobs. Phase 4 remains inactive and unaccepted.
