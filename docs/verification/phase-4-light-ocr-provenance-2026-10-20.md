# Phase 4 light-ocr candidate archive and notice audit — 2026-10-20

The isolated Debian 13 LXC candidate uses four exact npm packages: `@arcships/light-ocr` 0.5.8, `@arcships/light-ocr-runtime` 0.1.8, `@arcships/light-ocr-model-ppocrv6-small` 0.3.4, and `@arcships/light-ocr-linux-x64-gnu` 0.5.8. These versions and archive SHA-512 integrity strings are already in `services/documents/package-lock.json`; they were not inferred from a latest-release label. The official [light-ocr repository](https://github.com/arcships/light-ocr) describes the project as Apache-2.0, and its [model-bundle guidance](https://github.com/arcships/light-ocr/blob/main/docs/model-bundle.md) calls for pinned model artifacts and license metadata. Current upstream documentation is contextual evidence, not a substitute for the exact published archive and its bundled notices.

Four published archives were downloaded from their exact lockfile URLs into `/root/localai-phase4-validation/.localai/` outside Git. The target-only `tests/target/light-ocr-npm-cohort.mjs` verified each archive's SHA-512 against the committed lockfile, rejected traversal/link/special archive entries before temporary extraction, and compared every extracted file's size and SHA-256 against the installed candidate. All four matched: facade 10 files, runtime 12, model 24, Linux native 30. The Linux native archive was 27,033,567 bytes with SHA-512 `a3306f63169e54ba1acf1bf5026c792818736b9fac5420f8564f2004a57bd9bed53cf0de163cdbe3e393037d9c11a55e35d392cd4e7d482754e8cb1e3c4dabb1` (hex). The archive bytes bind the installed native package and its vendor manifest to the lockfile integrity.

The separate target-only `tests/target/light-ocr-native-inventory.mjs` rehashed all 29 files declared in the native package's `artifact-hashes.json`; only that manifest itself is excluded from its own list. It verified the 14 files in `license-inventory.json` against the declared file hashes. The vendor SBOM declares 11 packages and nonempty license identifiers. Its notice component names include OpenCV, zlib, carotene, Clipper, stb, nlohmann-json, ONNX Runtime, pdfium-native and Noto Sans SC. This is a verified inventory of vendor-supplied notices, **not** an independent determination that the SBOM or transitive license list is complete or legally sufficient.

The candidate was read only. The enrolled gateway remained PID 19963, `/var/lib/dpkg/status` remained SHA-256 `6472c8846aa1c77e2616b8d74b53818517e921a27048edbe61686527073c67fe`, and no Phase 4 document worker was activated. The earlier whole-tree inventory found no writable or non-root entries in this light-ocr candidate; its whole-tree hash is observational, not a release pin. Exact runtime payload construction, full independent transitive/native license review, compatibility under combined chat/OCR load, and installer enforcement remain required before Phase 4 acceptance.
