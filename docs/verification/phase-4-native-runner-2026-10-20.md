# Phase 4 native document runner checkpoint — 2026-10-20

The inactive root-supervisor candidate starts a one-request document worker in a named transient systemd service. The service uses a dynamic identity, a private mode-0700 runtime socket, a private network and device namespace, read-only system files, and explicit memory, swap, CPU, task and runtime limits. It cannot read the gateway vault or model directories. The caller supplies a root-owned worker executable from the fixed application tree; document requests cannot select a program, unit name or socket path. The runner checks that the unit has no main PID and is inactive or failed before it confirms cleanup or returns a result.

A root-only disposable Debian 13 proof used the real systemd unit and a synthetic English/Arabic TXT request. It also checked malformed request rejection before launch, a worker protocol error, startup cancellation, and a worker that emitted 256 KiB of diagnostics after readiness. The output test first failed: the runner reported a generic worker failure and could keep retaining data. The fix caps retained diagnostics at 64 KiB, interrupts any stage on overflow, stops the actual unit, and confirms it has no remaining main PID. The corrected proof passed, found no active document-job units, and found the enrolled gateway PID unchanged. Independent review found no remaining high-priority issue in this candidate; the reviewer did not independently execute the native proof.

Full validation on this source: Windows 217 passed with three POSIX-only skips; Debian 220/220 passed with zero skips. The native target proof is separate from the automated suite because it requires root and real systemd. The source has not been activated. Persistent supervision, the startup lock, job-to-unit identity binding, actual supervisor crash/restart and long-running OCR cancellation tests, authenticated document routes, and joint resource/release qualification remain required before Phase 4 acceptance.
